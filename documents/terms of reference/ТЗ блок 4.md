# Техническое задание: Модуль Transactional Outbox Engine (Движок фоновых задач и очередей)

Документ представляет собой полную инженерную спецификацию модуля **Transactional Outbox Engine** для реализации разработчиком в рамках архитектуры модульного монолита `reklama-bot-platform`.

---

## 1. Паспорт модуля и границы ответственности

* **Идентификатор модуля:** `outbox_engine`
* **Расположение в репозитории:** `src/modules/outbox_engine/`
* **Точка монтирования контрактов:** `src/shared/contracts/outbox.py`
* **Точка запуска рантайма:** `src/apps/worker_runner.py`

### 1.1. Входит в зону ответственности (In-Scope)

1. Реализация модели таблицы `outbox_tasks` и оптимизированных индексов для высококонкурентного чтения.
2. Безопасная конкурентная выборка созревших задач из PostgreSQL с использованием `SELECT ... FOR UPDATE SKIP LOCKED` и механизма распределенного лизинга (`locked_until`).
3. Диспетчеризация задач по зарегистрированным обработчикам модулей-потребителей (`channel_publisher`, `compensation`).
4. Управление жизненным циклом выполнения: перевод в статус `processed = TRUE`, фиксация ошибок в `last_error`.
5. Политика повторов (Retry Policy): экспоненциальный backoff с джиттером (jitter) для транзиентных сбоев.
6. **Специализированная обработка Rate Limit / FloodWait (429):** перенос времени запуска `execute_after` строго на интервал `retry_after` **без сжигания счетчика `retry_count**`.
7. Перевод невосстановимых задач в терминальный статус сбоя (Dead Letter / `FAILED`) и вызов хука компенсации.
8. Корректное завершение работы процесса (Graceful Shutdown) при получении сигналов `SIGINT` / `SIGTERM`.

### 1.2. НЕ входит в зону ответственности (Out-of-Scope)

* Генерация бизнес-задач при оформлении заказов (зона ответственности `order_domain`).
* Сетевые вызовы Telegram Bot API для отправки контента (зона ответственности `channel_publisher`).
* Сетевые вызовы API Т-Банка для отмены платежей (зона ответственности `payment_gateway` / `compensation`).
* Прием внешних вебхуков и обработка пользовательских команд в боте.

## 3. Схема базы данных и оптимизация индексов

### 3.1. DDL схемы таблицы `outbox_tasks`

```sql
CREATE TYPE outbox_task_type_enum AS ENUM (
    'PUBLISH_POST',             -- Публикация рекламного поста в канал
    'EXECUTE_PAYMENT_REFUND'    -- Выполнение отмены/возврата средств в банке
);

CREATE TABLE outbox_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_type outbox_task_type_enum NOT NULL,
    payload JSONB NOT NULL,
    
    -- Контроль исполнения и блокировок
    execute_after TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    locked_until TIMESTAMPTZ,
    retry_count INT NOT NULL DEFAULT 0,
    max_retries INT NOT NULL DEFAULT 5,
    
    -- Статусы
    processed BOOLEAN NOT NULL DEFAULT FALSE,
    failed_permanently BOOLEAN NOT NULL DEFAULT FALSE,
    last_error TEXT,
    
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Оптимизированный индекс для выборки готовых задач (SKIP LOCKED)
CREATE INDEX idx_outbox_queue ON outbox_tasks (execute_after, created_at)
WHERE processed = FALSE AND failed_permanently = FALSE;

-- Индекс для отслеживания зависших блокировок (Lease Check)
CREATE INDEX idx_outbox_lease ON outbox_tasks (locked_until)
WHERE processed = FALSE AND failed_permanently = FALSE AND locked_until IS NOT NULL;

```

## 4. Контракты интерфейсов (`src/shared/contracts/outbox.py`)

Для изоляции исполнителей задач от движка очередей используется протокол обработчика и типизированные доменные исключения.

```python
from enum import StrEnum
from typing import Any, Protocol
import uuid
from pydantic import BaseModel


class OutboxTaskType(StrEnum):
    PUBLISH_POST = "PUBLISH_POST"
    EXECUTE_PAYMENT_REFUND = "EXECUTE_PAYMENT_REFUND"


class TaskContextDTO(BaseModel):
    task_id: uuid.UUID
    task_type: OutboxTaskType
    payload: dict[str, Any]
    retry_count: int


# Исключения для управления жизненным циклом ретраев
class OutboxTaskError(Exception):
    """Базовое исключение ошибки обработки задачи."""
    pass


class RetryableTaskError(OutboxTaskError):
    """Транзиентная ошибка (сетевой таймаут, 5xx). Требует стандартного retry с backoff."""
    pass


class RateLimitTaskError(OutboxTaskError):
    """
    Ошибка лимита запросов (например, Telegram FloodWait / 429).
    Передает точное время ожидания в секундах.
    """
    def __init__(self, retry_after: int, message: str = "Rate limited"):
        super().__init__(message)
        self.retry_after = retry_after


class FatalTaskError(OutboxTaskError):
    """
    Фатальная ошибка (бот удален из канала, бан 403, невалидный payload).
    Задача немедленно маркируется failed_permanently, повторы отменяются.
    """
    pass


class IOutboxTaskHandler(Protocol):
    """Интерфейс обработчика конкретного типа задачи."""
    async def handle(self, context: TaskContextDTO) -> None:
        """
        Выполняет полезную нагрузку задачи.
        В случае сбоя выбрасывает RetryableTaskError, RateLimitTaskError или FatalTaskError.
        """
        ...

    async def on_fatal_failure(self, context: TaskContextDTO, error: str) -> None:
        """Вызывается при окончательном крахе задачи (исчерпаны попытки или FatalTaskError)."""
        ...

```

## 5. Алгоритм выборки задач (Poller Engine & Lease Locking)

### 5.1. Поллинг и конкурентный захват (`SKIP LOCKED`)

Воркер не держит открытую долгую транзакцию на время выполнения полезной нагрузки задачи (чтобы не исчерпать пул подключений Postgres и не блокировать таблицы).

Захват происходит в **две раздельные фазы**:

1. **Короткая транзакция захвата (Acquire Lease):** выборка пачки созревших задач и наложение временного лока (`locked_until`).
2. **Асинхронная обработка (Execute):** выполнение задач в пуле воркеров.
3. **Короткая транзакция завершения/ретрая (Complete / Fail):** снятие лока и обновление статуса.

#### SQL-запрос захвата пачки (Атомарный Acquire)

```sql
WITH candidate_tasks AS (
    SELECT id
    FROM outbox_tasks
    WHERE processed = FALSE
      AND failed_permanently = FALSE
      AND execute_after <= NOW()
      AND (locked_until IS NULL OR locked_until < NOW())
    ORDER BY execute_after ASC, created_at ASC
    LIMIT :batch_size
    FOR UPDATE SKIP LOCKED
)
UPDATE outbox_tasks t
SET locked_until = NOW() + (INTERVAL '1 second' * :lease_duration_seconds),
    updated_at = NOW()
FROM candidate_tasks c
WHERE t.id = c.id
RETURNING t.id, t.task_type, t.payload, t.retry_count, t.max_retries;

```

* `:batch_size`: конфигурируемый размер пачки (по умолчанию 10).
* `:lease_duration_seconds`: время аренды задачи (по умолчанию 60 секунд). Защищает от зависания задач при внезапном падении (kill -9) процесса воркера: через 60 секунд задача освободится и будет взята повторно.

## 6. Политика повторов и обработка Telegram FloodWait

### 6.1. Алгоритм Exponential Backoff with Full Jitter

Для стандартных транзиентных сбоев (`RetryableTaskError` или сетевые ошибки `HTTPError`):


$$\text{delay} = \min(\text{max\_backoff}, \text{base\_delay} \cdot 2^{\text{retry\_count}}) + \text{uniform}(0, \text{jitter})$$

* Базовая задержка (`base_delay`): 5 секунд.
* Максимальная задержка (`max_backoff`): 300 секунд (5 минут).
* Джиттер: случайное значение от 0 до 3 секунд для предотвращения эффекта "thundering herd".
* Инкремент счетчика: `retry_count = retry_count + 1`.

### 6.2. Специальная обработка RateLimitTaskError (429 FloodWait)

> **Критическое требование аудита:** при получении `TelegramRetryAfter` счетчик попыток `retry_count` **не должен сжигаться**. В противном случае после 2–3 ограничений FloodWait валидный оплаченный заказ будет помечен как сбойный.

#### SQL-запрос при `RateLimitTaskError`

```sql
UPDATE outbox_tasks
SET locked_until = NULL,
    execute_after = NOW() + (INTERVAL '1 second' * :retry_after),
    last_error = :error_message,
    updated_at = NOW()
WHERE id = :task_id;

```

* `retry_count` **не изменяется**.
* `locked_until` немедленно обнуляется, чтобы задача могла выполниться сразу по наступлении `execute_after`.
* Воркер продолжает работу над другими независимыми задачами.

### 6.3. Обработка фатального сбоя (Exhausted Retries / FatalTaskError)

Если `retry_count + 1 >= max_retries` или выброшено исключение `FatalTaskError`:

1. В базе фиксируется терминальный статус:
```sql
UPDATE outbox_tasks
SET processed = FALSE,
    failed_permanently = TRUE,
    locked_until = NULL,
    last_error = :error_message,
    updated_at = NOW()
WHERE id = :task_id;

```


2. Вызывается метод `handler.on_fatal_failure(context, error_message)`.
3. Модуль компенсации (`compensation`) получает управление для автоматического запуска отмены/возврата платежа.

### 8.1. Диспетчер задач (`dispatcher.py`)

```python
import logging
from src.shared.contracts.outbox import IOutboxTaskHandler, OutboxTaskType

logger = logging.getLogger(__name__)


class TaskDispatcher:
    def __init__(self) -> None:
        self._handlers: dict[OutboxTaskType, IOutboxTaskHandler] = {}

    def register_handler(
        self, task_type: OutboxTaskType, handler: IOutboxTaskHandler
    ) -> None:
        self._handlers[task_type] = handler
        logger.info("Зарегистрирован обработчик для Outbox-задач: %s", task_type)

    def get_handler(self, task_type: OutboxTaskType) -> IOutboxTaskHandler:
        handler = self._handlers.get(task_type)
        if not handler:
            raise ValueError(f"Обработчик для задачи {task_type} не зарегистрирован")
        return handler

```

### 8.2. Исполнитель задач (`executor.py`)

```python
from datetime import datetime, timezone, timedelta
import logging
import random
from sqlalchemy import update
from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession

from src.modules.outbox_engine.models import OutboxTaskModel
from src.shared.contracts.outbox import (
    FatalTaskError,
    IOutboxTaskHandler,
    RateLimitTaskError,
    RetryableTaskError,
    TaskContextDTO,
)

logger = logging.getLogger(__name__)


class TaskExecutor:
    def __init__(self, session_factory: async_sessionmaker[AsyncSession]):
        self.session_factory = session_factory

    async def execute_task(
        self,
        context: TaskContextDTO,
        max_retries: int,
        handler: IOutboxTaskHandler,
    ) -> None:
        try:
            # 1. Вызов бизнес-логики обработчика
            await handler.handle(context)

            # 2. Успешное завершение: помечаем processed = TRUE
            await self._mark_success(context.task_id)

        except RateLimitTaskError as rle:
            logger.warning(
                "Task %s столкнулась с Rate Limit. Пауза %s сек. Счётчик не сжигается.",
                context.task_id,
                rle.retry_after,
            )
            await self._handle_rate_limit(context.task_id, rle.retry_after, str(rle))

        except FatalTaskError as fte:
            logger.error("Фатальная ошибка задачи %s: %s", context.task_id, fte)
            await self._handle_fatal_failure(context, handler, str(fte))

        except Exception as exc:
            # Транзиентные и непредвиденные ошибки
            logger.warning(
                "Ошибка при исполнении задачи %s (попытка %s/%s): %s",
                context.task_id,
                context.retry_count + 1,
                max_retries,
                exc,
            )
            if context.retry_count + 1 >= max_retries:
                await self._handle_fatal_failure(
                    context, handler, f"Max retries exceeded: {exc}"
                )
            else:
                await self._handle_retryable_failure(context, str(exc))

    async def _mark_success(self, task_id) -> None:
        async with self.session_factory() as session:
            stmt = (
                update(OutboxTaskModel)
                .where(OutboxTaskModel.id == task_id)
                .values(
                    processed=True,
                    locked_until=None,
                    last_error=None,
                    updated_at=datetime.now(timezone.utc),
                )
            )
            await session.execute(stmt)
            await session.commit()

    async def _handle_rate_limit(
        self, task_id, retry_after: int, error_msg: str
    ) -> None:
        async with self.session_factory() as session:
            execute_after = datetime.now(timezone.utc) + timedelta(seconds=retry_after)
            stmt = (
                update(OutboxTaskModel)
                .where(OutboxTaskModel.id == task_id)
                .values(
                    locked_until=None,
                    execute_after=execute_after,
                    last_error=error_msg,
                    updated_at=datetime.now(timezone.utc),
                )
            )
            await session.execute(stmt)
            await session.commit()

    async def _handle_retryable_failure(
        self, context: TaskContextDTO, error_msg: str
    ) -> None:
        base_delay = 5.0
        max_delay = 300.0
        backoff = min(max_delay, base_delay * (2**context.retry_count))
        jitter = random.uniform(0.5, 3.0)
        delay_seconds = backoff + jitter

        execute_after = datetime.now(timezone.utc) + timedelta(seconds=delay_seconds)

        async with self.session_factory() as session:
            stmt = (
                update(OutboxTaskModel)
                .where(OutboxTaskModel.id == context.task_id)
                .values(
                    locked_until=None,
                    execute_after=execute_after,
                    retry_count=context.retry_count + 1,
                    last_error=error_msg,
                    updated_at=datetime.now(timezone.utc),
                )
            )
            await session.execute(stmt)
            await session.commit()

    async def _handle_fatal_failure(
        self, context: TaskContextDTO, handler: IOutboxTaskHandler, error_msg: str
    ) -> None:
        async with self.session_factory() as session:
            stmt = (
                update(OutboxTaskModel)
                .where(OutboxTaskModel.id == context.task_id)
                .values(
                    processed=False,
                    failed_permanently=True,
                    locked_until=None,
                    last_error=error_msg,
                    updated_at=datetime.now(timezone.utc),
                )
            )
            await session.execute(stmt)
            await session.commit()

        # Запуск компенсирующих действий
        try:
            await handler.on_fatal_failure(context, error_msg)
        except Exception as e:
            logger.critical(
                "Ошибка при вызове on_fatal_failure для задачи %s: %s",
                context.task_id,
                e,
                exc_info=True,
            )

```

### 8.3. Главный цикл оркестратора (`worker.py`)

```python
import asyncio
import logging
from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession
from src.modules.outbox_engine.config import OutboxConfig
from src.modules.outbox_engine.dispatcher import TaskDispatcher
from src.modules.outbox_engine.executor import TaskExecutor
from src.modules.outbox_engine.poller import TaskPoller
from src.shared.contracts.outbox import TaskContextDTO

logger = logging.getLogger(__name__)


class OutboxWorker:
    def __init__(
        self,
        session_factory: async_sessionmaker[AsyncSession],
        dispatcher: TaskDispatcher,
        config: OutboxConfig,
    ):
        self.session_factory = session_factory
        self.dispatcher = dispatcher
        self.config = config
        self.poller = TaskPoller(session_factory, config)
        self.executor = TaskExecutor(session_factory)
        self._semaphore = asyncio.Semaphore(config.max_concurrent_tasks)
        self._running = False

    async def run(self) -> None:
        self._running = True
        logger.info("Outbox Worker запущен. Конкурентность: %d", self.config.max_concurrent_tasks)

        while self._running:
            try:
                # 1. Захват созревших задач пачкой через SKIP LOCKED
                tasks = await self.poller.acquire_batch()

                if not tasks:
                    await asyncio.sleep(self.config.poll_interval_seconds)
                    continue

                # 2. Параллельный запуск задач под семафором
                for task_row in tasks:
                    await self._semaphore.acquire()
                    asyncio.create_task(self._process_task_wrapper(task_row))

            except asyncio.CancelledError:
                break
            except Exception as e:
                logger.exception("Ошибка цикла поллинга Outbox: %s", e)
                await asyncio.sleep(self.config.poll_interval_seconds)

    async def _process_task_wrapper(self, task_row) -> None:
        try:
            handler = self.dispatcher.get_handler(task_row.task_type)
            context = TaskContextDTO(
                task_id=task_row.id,
                task_type=task_row.task_type,
                payload=task_row.payload,
                retry_count=task_row.retry_count,
            )
            await self.executor.execute_task(
                context=context,
                max_retries=task_row.max_retries,
                handler=handler,
            )
        finally:
            self._semaphore.release()

    def stop(self) -> None:
        logger.info("Остановка Outbox Worker...")
        self._running = False

```

## 9. Граничные сценарии и отказоустойчивость

| Инцидент / Сбой | Поведение Outbox Engine | Гарантия надежности |
| --- | --- | --- |
| **Внезапная смерть процесса воркера (`kill -9`, OOM)** | Задача захвачена, но процесс упал до завершения. | Механизм Lease Lock: через `lease_duration_seconds` (60 сек) условие `locked_until < NOW()` станет истинным, и другой инстанс воркера заберет задачу. |
| **Telegram FloodWait (429)** | Обработчик `channel_publisher` получает `TelegramRetryAfter(retry_after=45)`. | Бросается `RateLimitTaskError(45)`. Движок сбрасывает `locked_until`, ставит `execute_after = NOW() + 45s`, **не увеличивая** `retry_count`. Заказ не теряется. |
| **Удаление бота из канала администратором (403 Forbidden)** | Обработчик публикации получает постоянную ошибку доступа. | Бросается `FatalTaskError`. Движок немедленно переводит задачу в `failed_permanently = TRUE` и вызывает `on_fatal_failure` для возврата средств заказчику. |
| **Падение соединения с PostgreSQL** | Ошибка во время выполнения `acquire_batch`. | Перехват `Exception`, логирование, пауза `poll_interval_seconds` и автоматический переподключение через connection pool `asyncpg`. |
| **Graceful Shutdown (SIGTERM)** | Процесс получает сигнал на завершение от Docker / K8s. | Флаг `_running = False`, ожидание завершения текущих активных корутин под семафором с таймаутом до 30 секунд. |

## 10. Критерии приемки (Definition of Done)

1. **Изоляция модуля:**
* Модуль `outbox_engine` не импортирует код бизнес-логики Telegram-бота, эквайринга или публикатора. Взаимодействие только через `IOutboxTaskHandler` и `src/shared/contracts/outbox.py`.


2. **Модульное тестирование (Unit Tests):**
* Тест расчета Exponential Backoff с проверкой добавления джиттера.
* Тест диспетчера: успешный роутинг по типу задачи и исключение при незарегистрированном типе.
* Тест обработки `RateLimitTaskError`: проверка, что `retry_count` не инкрементируется, а `execute_after` сдвигается на точное время.
* Тест обработки `FatalTaskError`: проверка вызова `on_fatal_failure`.


3. **Интеграционные тесты с реальной PostgreSQL (testcontainers / pytest-asyncio):**
* **Тест `SKIP LOCKED`:** запуск 3 параллельных воркеров на выборку из 10 готовых задач — ни одна задача не должна быть захвачена дважды одновременно.
* **Тест истечения Lease Lock:** задача с просроченным `locked_until = NOW() - 10s` успешно перехватывается новым воркером.
* **Тест успешного завершения:** задача корректно получает `processed = TRUE` и снимает `locked_until`.
