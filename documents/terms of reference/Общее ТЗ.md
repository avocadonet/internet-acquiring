### Архитектурная структура репозитория

Для параллельной разработки шестью исполнителями проект организуется по паттерну **Package-by-Feature (модульный монолит)** с жестким разделением через слой контрактов (`shared/contracts`). Это позволяет каждому разработчику писать код и тесты в изолированной директории, опираясь на интерфейсы (`Protocol`) и DTO, даже если смежные модули еще не готовы.

### Роли директорий и правила изоляции

| Сегмент | Назначение | Правило для разработчиков |
| --- | --- | --- |
| `src/shared/contracts/` | Базовые типы, структуры данных (DTO) и интерфейсы (`typing.Protocol`). | **Зона заморозки.** Изменения вносятся только по согласованию тимлида. Никакой сторонний модуль не может импортировать код другого модуля напрямую — взаимодействие разрешено **только** через типы из этой папки. |
| `src/modules/<name>/` | Рабочая зона конкретного разработчика. Внутри модуля находится его бизнес-логика, внутренние сервисы и локальные модели. | Разработчик модуля `A` не имеет права импортировать файлы из папки модуля `B`. Разрешены только импорты из `src/shared/*`. |
| `src/apps/` | Точки запуска рантаймов (композиционный корень / Composition Root). | Здесь происходит склейка модулей через Dependency Injection перед стартом процесса. |
| `tests/mocks/` | Набор готовых mock-классов, реализующих протоколы из `contracts`. | Позволяет тестировать модуль в изоляции: разработчик бота тестирует FSM с `MockOrderService`, не дожидаясь написания реальной логики в `order_domain`. |

### Карта запуска процессов

При деплое из одной кодовой базы поднимаются 3 независимых легковесных контейнера (или процесса):

1. **`bot_runner.py`** — запускает `modules/bot_ingress` (aiogram роутеры, Redis Debounce loop).
2. **`api_runner.py`** — запускает легковесный FastAPI веб-сервер с подключенным эндпоинтом из `modules/payment_gateway/webhook_router.py`.
3. **`worker_runner.py`** — запускает бесконечный цикл `modules/outbox_engine`, передавая управление в обработчики `channel_publisher` и `compensation`.
