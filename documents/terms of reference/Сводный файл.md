# Сводная спецификация интеграции и регламент развертывания платформы

### 1. Архитектурная карта взаимодействия и сквозные потоки данных

#### Сквозной сценарий 1: Успешная публикация (Happy Path)

1. **Сбор данных:** Пользователь отправляет пост и контакты боту (`bot_ingress`). Альбомы агрегируются в Redis через sliding window debounce (1.5 с).
2. **Создание заказа:** `bot_ingress` вызывает `IOrderService.create_order()`. Модуль `order_domain` обращается к `IPaymentClient.init_payment()` (`payment_gateway`), формирует чек 54-ФЗ с массивом `Receipt.Items` и фиксирует заказ в БД со статусом `PENDING`. Пользователь получает URL оплаты.
3. **Оплата:** Банк отправляет вебхук `CONFIRMED`. Модуль `payment_gateway` проверяет `TerminalKey` и подпись `Token`, после чего вызывает `IOrderInternalService.handle_payment_succeeded()`.
4. **Транзакция Outbox:** `order_domain` в единой ACID-транзакции переводит заказ в статус `PAID` и создает запись в `outbox_tasks` с типом `PUBLISH_POST`.
5. **Публикация:** `outbox_engine` захватывает задачу через `SELECT ... FOR UPDATE SKIP LOCKED` и передает ее в `channel_publisher`. Пост публикуется в канале, статус заказа обновляется на `PUBLISHED`, задача помечается `processed = TRUE`.

#### Сквозной сценарий 2: Отмена и возврат средств (Compensation Flow)

1. **Сбой публикации:** Бот удален из канала (`TelegramForbiddenError`) или исчерпан лимит попыток.
2. **Инициация компенсации:** `channel_publisher` вызывает `on_fatal_failure()`, который дергает `IOrderInternalService.handle_publish_failed()`.
3. **Фиксация сбоя:** `order_domain` переводит заказ в статус `REFUND_REQUIRED` и атомарно создает Outbox-задачу `EXECUTE_PAYMENT_REFUND`.
4. **Возврат:** `outbox_engine` передает задачу в модуль `compensation` (`refund_handler`). Модуль вызывает метод `/v2/Cancel` через `payment_gateway`, переводит заказ в статус `REFUNDED`, отправляет уведомление пользователю в бота и генерирует алерт дежурным администраторам.

### 2. Точки входа рантайм-процессов (Composition Roots)

Кодовая база запускает три изолированных процесса. Каждый процесс подтягивает только требуемые ему модули.

| Процесс | Точка запуска | Подключаемые модули | Назначение |
| --- | --- | --- | --- |
| **Bot Runner** | `src/apps/bot_runner.py` | `bot_ingress`, `order_domain`, `payment_gateway` | Poller/Webhook Telegram-бота, FSM, фоновый сборщик альбомов Redis ZSET. |
| **API Runner** | `src/apps/api_runner.py` | `payment_gateway`, `order_domain` | Легковесный ASGI HTTP-сервер (FastAPI/Uvicorn) для приема вебхуков от банка. |
| **Worker Runner** | `src/apps/worker_runner.py` | `outbox_engine`, `channel_publisher`, `compensation`, `order_domain`, `payment_gateway` | Демон поллинга задач БД, диспетчеризация публикаций и возвратов средств. |

#### 3.2. Dockerfile (`deploy/Dockerfile`)

```dockerfile
FROM python:3.12-slim AS base

ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    PIP_NO_CACHE_DIR=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1

WORKDIR /app

# Установка системных зависимостей
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Установка зависимостей Python
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Копирование исходного кода
COPY src/ ./src/
COPY migrations/ ./migrations/
COPY alembic.ini .

# Создание непривилегированного пользователя для безопасности
RUN adduser --disabled-password --gecos "" appuser && chown -R appuser:appuser /app
USER appuser

CMD ["python", "-m", "src.apps.bot_runner"]

```

### 4. Пошаговый регламент развертывания и запуска

#### Шаг 1. Клонирование и подготовка конфигурации

```bash
git clone <repository_url> reklama-bot-platform
cd reklama-bot-platform

# Скопировать шаблон конфигурации
cp deploy/env.example .env

# Заполнить реальные токены и ключи в .env:
# - TELEGRAM_BOT_TOKEN
# - TELEGRAM_ADMIN_CHAT_ID
# - TBANK_TERMINAL_KEY
# - TBANK_SECRET_PASSWORD

```

#### Шаг 2. Запуск инфраструктуры и миграций

```bash
# Сборка образов и запуск всех контейнеров в фоновом режиме
docker compose -f deploy/docker-compose.yml up --build -d

# Проверка статуса запуска всех контейнеров
docker compose -f deploy/docker-compose.yml ps

```

#### Шаг 3. Проброс внешнего туннеля для платежного вебхука (Локальная разработка)

Банк требует публичный HTTPS-адрес для доставки уведомлений:

```bash
# Запуск туннеля к сервису API (порт 8000) через ngrok или cloudflared
ngrok http 8000

```

Скопируйте полученный HTTPS URL (например, `[https://abc1234.ngrok-free.app](https://abc1234.ngrok-free.app)`) и пропишите в Личном кабинете Т-Бизнеса эндпоинт нотификаций:
`[https://abc1234.ngrok-free.app/api/v1/payments/tbank/webhook](https://abc1234.ngrok-free.app/api/v1/payments/tbank/webhook)`

### 5. Чек-лист сквозной проверки работоспособности (End-to-End Smoke Test)

1. **Проверка Ingress и FSM:**
* Открыть диалог с ботом, нажать `/start`.
* Выбрать рекламный канал.
* Отправить альбом из 3 фотографий с подписью. Убедиться, что бот корректно объединил их и выдал единое превью.
* Нажать «Поделиться контактом». Убедиться, что телефон нормализован к формату `+79XXXXXXXXX`.


2. **Проверка инициализации платежа:**
* Нажать «Перейти к оплате».
* Проверить в логах `api` / `bot` факт обращения к методу `/v2/Init`.
* Перейти по полученной ссылке на тестовую платежную форму Т-Банка.


3. **Проверка подтверждения и публикации (Happy Path):**
* Оплатить заказ тестовой картой (успешная оплата).
* Убедиться, что в логах `api` появился запрос `POST /webhook` со статусом `CONFIRMED` и ответом `200 OK` (тело `OK`).
* В логах `worker` зафиксировать выборку задачи `PUBLISH_POST` через `SKIP LOCKED`.
* Проверить появление поста в целевом Telegram-канале с корректным текстом и медиафайлами.


4. **Проверка компенсации (Refund Path):**
* Временно отозвать права бота на публикацию в тестовом канале (или разлогинить).
* Создать и оплатить новый заказ.
* Убедиться, что после ошибки `TelegramForbiddenError` воркер перевел задачу в `failed_permanently`, домен сменил статус на `REFUND_REQUIRED`, а модуль `compensation` вызвал `/v2/Cancel`.
* Проверить поступление сервисного сообщения в бот пользователю об отмене и отправку алерта в канал администраторов `TELEGRAM_ADMIN_CHAT_ID`.
