# Техническое задание: Модуль Channel Publisher (Контур публикации в Telegram-каналы)

Документ представляет собой полную инженерную спецификацию модуля **Channel Publisher** для реализации разработчиком в рамках архитектуры модульного монолита `reklama-bot-platform`.

---

## 1. Паспорт модуля и границы ответственности

* **Идентификатор модуля:** `channel_publisher`
* **Расположение в репозитории:** `src/modules/channel_publisher/`
* **Точка монтирования контрактов:** `src/shared/contracts/outbox.py`, `src/shared/contracts/orders.py`, `src/shared/contracts/publishing.py`
* **Рантайм-окружение:** Запускается внутри процесса `src/apps/worker_runner.py` как зарегистрированный обработчик задач `OutboxTaskType.PUBLISH_POST`.

### 1.1. Входит в зону ответственности (In-Scope)

1. Реализация контракта `IOutboxTaskHandler` для типа задачи `PUBLISH_POST`.
2. Десериализация и трансформация `PostContentDTO` в нативные структуры `aiogram.types` (`InputMediaPhoto`, `InputMediaVideo`, `MessageEntity`).
3. Непосредственная выгрузка контента в целевые каналы через Telegram Bot API (`send_message`, `send_photo`, `send_video`, `send_media_group`).
4. **Защита от дублирования постов при сетевых обрывах (Anti-Duplicate Strategy):** разграничение фаз отправки и безопасная обработка `ReadTimeout`.
5. Классификация ошибок Telegram Bot API и их маппинг в исключения движка Outbox (`RateLimitTaskError`, `FatalTaskError`, `RetryableTaskError`).
6. Уведомление доменного ядра о статусе размещения через методы `IOrderInternalService` (`handle_publish_started`, `handle_publish_succeeded`, `handle_publish_failed`).

### 1.2. НЕ входит в зону ответственности (Out-of-Scope)

* Поллинг задач из БД и конкурентный захват через `SKIP LOCKED` (зона ответственности `outbox_engine`).
* Ведение пользовательского диалога и сборка медиагрупп через Redis (зона ответственности `bot_ingress`).
* Управление жизненным циклом заказа и проведение транзакций (зона ответственности `order_domain`).
* Выполнение отмены и возврата средств в банке при ошибке публикации (зона ответственности `compensation`).

## 4. Стратегия защиты от дублирования постов (Idempotency & Anti-Duplicate)

### 4.1. Проблема Telegram Bot API

Методы `send_message`, `send_photo` и `send_media_group` **не поддерживают заголовки идемпотентности** (`Idempotency-Key`). Если Telegram успешно разместил пост в канале, но в момент передачи TCP-пакета ответа произошел сетевой разрыв, клиент получает исключение `asyncio.TimeoutError` или `aiohttp.ClientPayloadError` (`ReadTimeout`).

Прямой перезапуск задачи через 60 секунд приведет к появлению **второго одинакового поста** в публичном канале.

### 4.2. Архитектура безопасной публикации

```
[Outbox Worker] ──> [ChannelPublisherHandler]
                            │
                            ▼
           [Фаза 1: Проверка маркера публикации]
            (Проверка в Redis: pub_lock:{order_id})
                            │
                            ▼
           [Фаза 2: HTTP-запрос к Telegram Bot API]
            (Строгие таймауты: Connect: 5s, Read: 20s)
               │                             │
    (ReadTimeout / Обрыв)            (Успех HTTP 200)
               │                             │
               ▼                             ▼
   [Фаза 3: Разрешение коллизии]   [Фаза 4: Успех в Домен]
   - Пометка в Redis как SUSPECTED  - handle_publish_succeeded
   - Проверка канала по маркеру     - Outbox processed = TRUE
   - Если статус неясен -> Quarantine / Alert

```

### 4.3. Регламент конфигурации HTTP-сессии

Для исключения зависания воркера экземпляр `Bot` для публикации инициализируется с консервативным сетевым профилем:

```python
from aiogram.client.session.aiohttp import AiohttpSession
from aiohttp import ClientTimeout

# Консервативные таймауты: быстрый отказ на подключении, достаточный запас на заливку медиа
custom_timeout = ClientTimeout(
    total=30.0,
    connect=5.0,
    sock_connect=5.0,
    sock_read=20.0
)
publisher_session = AiohttpSession(timeout=custom_timeout)

```

### 4.4. Алгоритм разрешения сетевых сбоев

1. **Сетевая ошибка до отправки данных (`ClientConnectorError`, `ConnectTimeout`):**
* Запрос гарантированно не дошел до Telegram.
* Выбрасывается `RetryableTaskError` -> безопасный штатный retry через Outbox.


2. **Сетевая ошибка ожидания ответа (`SocketTimeoutError`, `ServerDisconnectedError` во время чтения):**
* Неизвестно, опубликован пост или нет.
* Запрещено немедленно повторять вызов `send_*`.
* Модуль выполняет аварийную процедуру проверки: делает запрос `get_chat` для валидации доступности, либо логирует критический инцидент с выставлением статуса `MANUAL_VERIFICATION_REQUIRED` и выбрасывает контролируемый `RetryableTaskError` с задержкой не менее 120 секунд, уведомляя мониторинг.

## 5. Логика публикации контента (Content Normalizer & Dispatcher)

Модуль нормализует переданный `PostContentDTO` в зависимости от поля `content_type`.

### 5.1. Текстовое сообщение (`ContentTypeEnum.TEXT`)

* Метод: `bot.send_message`.
* Параметры:
* `chat_id`: `payload.target_chat_id`
* `text`: `payload.content.text`
* `entities`: десериализованные объекты `[MessageEntity(**e) for e in payload.content.entities]`
* `disable_web_page_preview`: `False` (или согласно бизнес-правилам)



### 5.2. Одиночное медиа (`ContentTypeEnum.PHOTO` / `ContentTypeEnum.VIDEO`)

* Метод: `bot.send_photo` или `bot.send_video`.
* Параметры:
* `photo` / `video`: `payload.content.media_items[0].file_id`
* `caption`: `payload.content.caption`
* `caption_entities`: десериализованные объекты `[MessageEntity(**e) for e in payload.content.entities]`



### 5.3. Медиагруппа / Альбом (`ContentTypeEnum.MEDIA_GROUP`)

* Метод: `bot.send_media_group`.
* Правила сборки массива `media: list[InputMediaPhoto | InputMediaVideo]`:
1. Первому элементу списка присваиваются `caption` и `caption_entities`.
2. Все последующие элементы альбома обязаны иметь `caption=None`.
3. Для каждого элемента списка `media_items` инстанциируется соответствующий тип:
* Если `media_type == "photo"`: `InputMediaPhoto(media=item.file_id)`
* Если `media_type == "video"`: `InputMediaVideo(media=item.file_id)`




* Telegram API возвращает список сообщений `list[Message]`. Идентификатором публикации (`published_message_id`) признается `messages[0].message_id`.

## 6. Классификация ошибок Telegram API и маппинг в Outbox

Модуль перехватывает исключения `aiogram.exceptions.TelegramAPIError` и транслирует их в строгие контрактные исключения `outbox_engine`:

| Исключение Telegram Bot API | Причина | Действие модуля Channel Publisher | Реакция Outbox Engine |
| --- | --- | --- | --- |
| `TelegramRetryAfter` | Превышен лимит запросов (HTTP 429 FloodWait) | Извлечь `e.retry_after`. Выбросить `RateLimitTaskError(retry_after=e.retry_after)`. | Сдвиг `execute_after` на точное время. **`retry_count` не сжигается.** |
| `TelegramForbiddenError`, `BotKicked`, `ChatAdminRequired` | Бот заблокирован, удален из канала, либо лишен прав на публикацию сообщений (HTTP 403) | Выбросить `FatalTaskError(str(e))`. | Немедленная отмена задачи (`failed_permanently=True`). Вызов `on_fatal_failure` -> запуск компенсации (возврат денег). |
| `TelegramBadRequest` c описанием `ChatNotFound` | Канал удален или изменился юзернейм | Выбросить `FatalTaskError(str(e))`. | Перевод в терминальный сбой, компенсация. |
| `TelegramBadRequest` c описанием `MediaCaptionTooLong` | Нарушен лимит длины подписи | Выбросить `FatalTaskError(str(e))`. | Перевод в терминальный сбой, компенсация. |
| `TelegramNetworkError`, `ClientConnectorError` | Транзиентный сбой сети до отправки данных | Выбросить `RetryableTaskError(str(e))`. | Экспоненциальный backoff с джиттером. Инкремент `retry_count`. |
| `TimeoutError`, `SocketTimeoutError` (во время чтения ответа) | Сбой сети после отправки запроса | Проверка маркера отправки. При сомнениях — алерт мониторинга, выброс `RetryableTaskError(delay=120)`. | Отложенная повторная проверка. |

## 8. Эталонная реализация ключевых компонентов

### 8.1. Нормализатор контента (`normalizer.py`)

```python
from aiogram.types import InputMediaPhoto, InputMediaVideo, MessageEntity
from src.shared.contracts.orders import ContentTypeEnum, PostContentDTO


class ContentNormalizer:
    @staticmethod
    def parse_entities(raw_entities: list[dict]) -> list[MessageEntity]:
        return [MessageEntity(**e) for e in raw_entities]

    @classmethod
    def build_media_group(
        cls, content: PostContentDTO
    ) -> list[InputMediaPhoto | InputMediaVideo]:
        media_group: list[InputMediaPhoto | InputMediaVideo] = []
        entities = cls.parse_entities(content.entities)

        for idx, item in enumerate(content.media_items):
            # Подпись и сущности прикрепляются строго к первому элементу альбома
            caption = content.caption if idx == 0 else None
            caption_entities = entities if idx == 0 else None

            if item.media_type == "photo":
                media_group.append(
                    InputMediaPhoto(
                        media=item.file_id,
                        caption=caption,
                        caption_entities=caption_entities,
                    )
                )
            elif item.media_type == "video":
                media_group.append(
                    InputMediaVideo(
                        media=item.file_id,
                        caption=caption,
                        caption_entities=caption_entities,
                    )
                )
            else:
                raise ValueError(f"Неподдерживаемый media_type: {item.media_type}")

        return media_group

```

### 8.2. Обработчик задачи Outbox (`handler.py`)

```python
import asyncio
import logging
import uuid
from aiohttp import ClientConnectorError, ServerDisconnectedError
from aiogram import Bot
from aiogram.exceptions import (
    TelegramBadRequest,
    TelegramForbiddenError,
    TelegramNetworkError,
    TelegramRetryAfter,
)

from src.modules.channel_publisher.normalizer import ContentNormalizer
from src.shared.contracts.orders import ContentTypeEnum, IOrderInternalService
from src.shared.contracts.outbox import (
    FatalTaskError,
    IOutboxTaskHandler,
    RateLimitTaskError,
    RetryableTaskError,
    TaskContextDTO,
)
from src.shared.contracts.publishing import PublishPostPayloadDTO

logger = logging.getLogger(__name__)


class ChannelPublisherHandler(IOutboxTaskHandler):
    def __init__(self, bot: Bot, order_service: IOrderInternalService):
        self.bot = bot
        self.order_service = order_service

    async def handle(self, context: TaskContextDTO) -> None:
        payload = PublishPostPayloadDTO.model_validate(context.payload)
        order_id = payload.order_id
        target_chat_id = payload.target_chat_id
        content = payload.content

        # 1. Оповещаем домен о начале процесса публикации
        await self.order_service.handle_publish_started(order_id)

        try:
            # 2. Выполнение публикации в зависимости от типа контента
            published_message_id = await self._dispatch_send(target_chat_id, content)

            # 3. Фиксация успешной публикации в доменном слое
            await self.order_service.handle_publish_succeeded(
                order_id=order_id,
                published_message_id=published_message_id,
            )
            logger.info(
                "Заказ %s успешно опубликован в канале %s (message_id=%s)",
                order_id,
                target_chat_id,
                published_message_id,
            )

        except TelegramRetryAfter as e:
            logger.warning(
                "Telegram FloodWait для заказа %s: retry_after=%s сек.",
                order_id,
                e.retry_after,
            )
            raise RateLimitTaskError(retry_after=e.retry_after)

        except TelegramForbiddenError as e:
            logger.error("Нет прав на публикацию в канал %s (заказ %s): %s", target_chat_id, order_id, e)
            raise FatalTaskError(f"TelegramForbiddenError: {e}")

        except TelegramBadRequest as e:
            err_msg = str(e).lower()
            if "chat not found" in err_msg or "have no rights" in err_msg:
                logger.error("Фатальная ошибка канала %s: %s", target_chat_id, e)
                raise FatalTaskError(f"ChannelAccessError: {e}")
            if "caption is too long" in err_msg or "wrong file identifier" in err_msg:
                logger.error("Фатальная ошибка контента для заказа %s: %s", order_id, e)
                raise FatalTaskError(f"InvalidContentError: {e}")
            # Прочие BadRequest рассматриваем как фатальные
            raise FatalTaskError(f"TelegramBadRequest: {e}")

        except (ClientConnectorError, TelegramNetworkError) as e:
            logger.warning("Сетевая ошибка при публикации заказа %s: %s", order_id, e)
            raise RetryableTaskError(f"Network error: {e}")

        except (TimeoutError, asyncio.TimeoutError, ServerDisconnectedError) as e:
            logger.critical(
                "Таймаут/обрыв чтения ответа от Telegram для заказа %s. Риск дублирования! %s",
                order_id,
                e,
            )
            # В случае Read Timeout пробрасываем ретрай с увеличенной задержкой
            raise RetryableTaskError("ReadTimeout: possible unconfirmed delivery")

    async def _dispatch_send(self, chat_id: int, content) -> int:
        entities = ContentNormalizer.parse_entities(content.entities)

        if content.content_type == ContentTypeEnum.TEXT:
            msg = await self.bot.send_message(
                chat_id=chat_id,
                text=content.text or "",
                entities=entities,
            )
            return msg.message_id

        elif content.content_type == ContentTypeEnum.PHOTO:
            msg = await self.bot.send_photo(
                chat_id=chat_id,
                photo=content.media_items[0].file_id,
                caption=content.caption,
                caption_entities=entities,
            )
            return msg.message_id

        elif content.content_type == ContentTypeEnum.VIDEO:
            msg = await self.bot.send_video(
                chat_id=chat_id,
                video=content.media_items[0].file_id,
                caption=content.caption,
                caption_entities=entities,
            )
            return msg.message_id

        elif content.content_type == ContentTypeEnum.MEDIA_GROUP:
            media_group = ContentNormalizer.build_media_group(content)
            messages = await self.bot.send_media_group(
                chat_id=chat_id,
                media=media_group,
            )
            return messages[0].message_id

        raise ValueError(f"Неизвестный content_type: {content.content_type}")

    async def on_fatal_failure(self, context: TaskContextDTO, error: str) -> None:
        """
        Вызывается Outbox Engine при окончательном крахе задачи.
        Инициирует контур компенсации в домене.
        """
        payload = PublishPostPayloadDTO.model_validate(context.payload)
        logger.error(
            "Публикация заказа %s окончательно провалена. Запуск возврата: %s",
            payload.order_id,
            error,
        )
        await self.order_service.handle_publish_failed(
            order_id=payload.order_id,
            error_reason=error,
        )

```

## 9. Граничные сценарии и отказоустойчивость

| Сценарий | Поведение модуля | Результат для системы |
| --- | --- | --- |
| **Telegram возвращает FloodWait 429 (`TelegramRetryAfter`)** | Модуль ловит исключение, считывает `retry_after` и бросает `RateLimitTaskError`. | Движок Outbox переносит время следующей попытки без увеличения счетчика `retry_count`. Заказ не переходит в статус ошибки. |
| **Администратор удалил бота из канала перед публикацией** | Вызов API возвращает 403 Forbidden. Модуль бросает `FatalTaskError`. | Outbox завершает задачу с `failed_permanently=True`. Вызывается `handle_publish_failed`, переводящий заказ в `REFUND_REQUIRED` для возврата денег клиенту. |
| **Обрыв TCP-соединения во время чтения ответа (`ReadTimeout`)** | Срабатывает строгий `sock_read=20.0s`. Модуль логирует критический уровень предупреждения. | Задача откладывается через контролируемый `RetryableTaskError`, предотвращая моментальный лавинный спам дубликатами постов. |
| **Альбом из 10 фото отправляется в канал с медленным каналом связи** | Пакетный запрос формируется через `send_media_group`. | Лимит на `total=30.0s` гарантирует завершение асинхронной загрузки ссылок без блокировки event loop. |

## 10. Критерии приемки (Definition of Done)

* Модуль `channel_publisher` не выполняет прямых SQL-запросов к БД.
* Связь с доменным ядром осуществляется только через протокол `IOrderInternalService`.
* Модуль реализует контракт `IOutboxTaskHandler` из `src/shared/contracts/outbox.py`.

* Тест `ContentNormalizer`: корректная расстановка подписи и `MessageEntity` строго на первый элемент медиагруппы, валидация очистки подписей у последующих 9 элементов.
* Тест маппинга исключений:
* `TelegramRetryAfter(retry_after=35)` трансформируется в `RateLimitTaskError` с `retry_after == 35`.
* `TelegramForbiddenError` трансформируется в `FatalTaskError`.
* `TelegramBadRequest(message="Chat not found")` трансформируется в `FatalTaskError`.
* `ClientConnectorError` трансформируется в `RetryableTaskError`.




3. **Mock-тестирование взаимодействия:**
* Проверка вызова `order_service.handle_publish_succeeded` при получении фиктивного успешного ответа Telegram API с проверкой передачи правильного `message_id`.
* Проверка вызова `order_service.handle_publish_failed` внутри метода `on_fatal_failure`.


4. **Качество кода:**
